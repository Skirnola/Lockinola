# Lockinola

Personal learning workspace for Iqbal, preparing for graduation in March/April 2027 and a subsequent IT career, potentially in Japan. N2 is a long-term Japanese goal, not a promised graduation outcome.

## Agreed learning tracks

- Coding: starts at beginner Python (currently familiar with if/else), then loops, functions, collections, debugging, tests, complexity, data structures, BFS/DFS, problem solving, and practical projects. Add Go and JavaScript/TypeScript later.
- Cloud/DevOps: Linux and networking foundations, containers, local Floci labs, infrastructure tools, then real AWS/GCP/Azure based on demonstrated readiness. Start with one real provider. No requirement to stay on Floci until 2027.
- Japanese: starts with no kana knowledge. Daily kana/pronunciation practice, followed by interleaved vocabulary, grammar, listening, reading, and introductory kanji. Support external lessons.
- All tracks can include videos, readings, courses, certification preparation, practical tasks, explanations, and later recall. Reviewed resource links and source-grounded quizzes are required in the curriculum stage.

## Learning and assessment

Review → learn → attempt → feedback → retry → revisit later.

AI provides explanations, constrained exercise variations, hints, and feedback. Coding correctness uses executable tests. Cloud lab verification requires actual checks or clearly labelled submitted evidence. Japanese fixed-answer checks use accepted answers; open-ended work uses explained feedback.

Distinguish content completion, attempts, help received, independent success, retention, and earned certification. Time/XP measure effort; topic mastery requires evidence. Missed days do not erase earned progress. Repeated submissions cannot award duplicate completion credit.

## Stage 1 design decisions

Warm editorial minimalism with retro stationery details: paper and sand surfaces, ink rules, cobalt actions, coral status marks, and restrained yellow highlights. The interface uses open editorial sections and sparse hard shadows rather than a dark dashboard or a page full of rounded cards. Copy stays direct and practical. No external image/font dependencies, autoplay, continuous motion, fabricated analytics, paid API, database, or deployment.

Stage 10 remains unpublished. Local mode opens normally and keeps records in the current browser. Hosted mode fails closed unless a password of at least 12 characters and a signing secret of at least 32 characters are configured. Successful access uses a seven-day signed, HttpOnly, Secure, SameSite=Strict cookie; failed sign-ins are rate-limited. The tutor, Python proxy, and cloud-readiness proxy enforce the same session boundary. The settings dialog shows release readiness, validates the current backup format with a round trip, reports AI cost configuration without exposing secrets, and distinguishes browser-local records from hosting. Cross-device transfer is manual export and restore only. The Python runner and Floci remain private local services. No publication, data migration, cloud login, or billable resource is performed by Stage 10.

## Future implementation constraints

Keep keys server-side. Budget and monitor API usage. Run submitted code in isolation. Do not expose local Floci directly to the internet. Local verification should check specified resources with narrowly scoped access. Real cloud tasks need permission/cost/cleanup understanding and a user-chosen spending limit.
